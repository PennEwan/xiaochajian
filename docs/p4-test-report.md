## 6. 测试中发现并修复的问题

| # | 问题 | 修复 |
|---|---|---|
| 1 | 新的上传进程首次检查门槛时不会清除上一个进程留下的「已停止」原因，状态页会一直显示已停止 | 首次判定总是写入 |
| 2 | 「从未检查过更新」被当成"在 1970 年检查过"，只是因为真实时间戳很大才碰巧到期 | 缺少检查时间即视为到期 |
| 3 | 控制面板操作完成后，结果提示立刻被「正在检测…」覆盖且不会消失 | 操作后的自动刷新不显示检测提示；检测完成时清除 |
| 4 | 为消除 ResourceWarning 在 `AppServer.close()` 中关闭 stdout，在全新 Codex 配置目录中会**永久卡住**：app-server 的子进程（官方插件市场的 `git fetch`）继承了管道 | 撤销该改动并注明原因（该类同时被安装步骤使用：若未发现，用户安装时可能卡住） |
| 5 | 无登录的临时 Codex 配置中，普通回合会一直等待模型 | 验收改用本机模拟模型（自定义 model provider），回合 0.1–0.4 s 完成 |
| 6 | 验收脚本：事件名大小写（app-server 用 camelCase）、临时目录中只读的 git 对象文件、残留的 `git fetch` 进程 | 脚本修正（非产品问题） |

## 7. 代码审查

独立审查（只读；逐个读了 P4 全部模块与对 ctr 的改动，并在仓库外做了实验）结论为「修复后可合并」：没有严重问题，6 个重要问题、11 个次要问题。安全相关的部分（不写信任项、配置编辑先校验后替换、宿主门槛失败即拦、更新包校验、CDK 拦截）评价为扎实。全部重要问题与大部分次要问题已修复并补测试：

| # | 级别 | 问题 | 修复 |
|---|---|---|---|
| 1 | 重要 | 所有恢复提示都让用户点「重新检测」，但它只刷新、不会重新注册插件 | 「重新检测」执行修复：兼容而未注册 → 注册；不兼容而仍注册 → 停用；面板从插件缓存运行时用安装时记录的安装目录 |
| 2 | 重要 | 用户禁用插件后更新：被误判为不兼容并移除插件 | 实测发现更糟：`codex plugin add` 会把禁用的插件**改回启用**。安装步骤记住用户的选择，通过 App 同一接口 `config/value/write` 恢复禁用，不再误判；验收新增两项检查 |
| 3 | 重要 | 面板与每日更新检查从无控制台的进程启动 codex.exe / PowerShell，会闪出控制台窗口 | 所有子进程加 `CREATE_NO_WINDOW`；提示模式的更新检查不再启动 codex.exe |
| 4 | 重要 | 面板用上传进程留下的旧状态，插件已禁用时仍可能显示「记录并上传中」 | 优先使用 Codex 配置的当前状态 |
| 5 | 重要 | 降级时「暂停」按钮不可用；读不到版本号被当作不兼容；提示说"已停用插件"但实际没有 | 暂停任何时候可用；新增 `unknown`（不做任何改动）；插件仍注册时的提示如实说明出路 |
| 6 | 重要 | 离线卸载并删除本机数据：设备凭证与待发送的删除请求被删，后台数据再也无法删除，提示却说可以 | 只保留发送所需的文件，重装后自动发送，提示按实际情况区分 |
| 7 | 次要 | 配置清理：全局合并空行会破坏多行字符串；吞掉下一个表上方的注释；显式父表导致校验失败；解码 / 占用错误会抛出 | 只在删除处合并；注释归还给下一个表；比较前忽略空表；所有错误如实报告 |
| 8 | 次要 | 后台地址末尾带 `/` 时暂停后需重新同意，队列中的内容不再上传 | 比较前规范化地址 |
| 9 | 次要 | 分发过程中异常时 `/充值 CDK` 会发给模型 | 任何异常仍拦截两个命令 |
| 10 | 次要 | 状态文件固定临时文件名，并发写可能失败并吞掉记录提示 | 每进程每线程独立临时文件；更新提示单独兜底 |
| 11 | 次要 | 更新清单读取中途断开未被识别，检查进程每 5 分钟重来 | 记为 network 并记录检查时间 |
| 12 | 次要 | 自动更新：静默删除开发版插件、安装后弹出面板抢焦点、可能打断进行中的兑换、可并发安装 | 更新不再处理开发版插件；`/UPDATE=auto` 不打开面板；充值窗口开着时推迟；`SetupMutex`；升级前只结束常驻 pythonw，不动 Hook 进程 |
| 13 | 次要 | 卸载界面不报告失败、保留的数据与缺失的运行时；配置备份（可能含密钥）一直保留 | 逐项提示；校验通过后删除备份 |
| 14 | 次要 | 面板打开时未检查更新；充值失败提示指向不存在的「充值.cmd」 | 打开面板时检查（24 小时节流）；提示改为开始菜单 |
| 15 | 次要 | 清理开发版插件时即使卸载失败也删除其市场表 | 只清理已卸载插件遗留的信任项，市场交给 Codex 自己的命令 |
| 16 | 次要 | 每个 Hook 都加载 urllib / ssl（约 35 ms） | 按需加载；实测中位数 465 → 428 ms |

未采纳 / 记为限制：更新清单用内嵌公钥签名（审查建议）——目前依赖 HTTPS + 清单中的 SHA-256，记入已知限制；`product.json` 的 `tested_apps` 仅作记录，判定只看内核版本。

| 项目 | 原因 | 计划 |
|---|---|---|
| 桌面 App 中「全部信任」、`/充值` 弹窗与拦截提示的界面表现、`/记录` | 需要用户在真实 App 中操作 | `docs/p4-manual-test.md`（20 步） |

| 用户真实环境的「全新安装」 | 需先卸载本机的开发版插件（`ctr-local`），要改用户真实的 `~/.codex`，须用户同意 | 用户确认后按手测清单执行 |

## 9. 已知限制

| 限制 | 说明 |
|---|---|
| 未签名 | 没有代码签名证书：下载与运行时 SmartScreen 显示「未知发布者」，用户需点「仍要运行」；部分杀毒软件可能拦截未签名的安装包或 `pythonw.exe`。正式发布前应购买证书并签名安装包与卸载程序 |
| 信任无法自动化 | Codex 要求用户亲自点「全部信任」；`hooks.json` 改动的更新需要重新信任（清单标记 `requires_retrust`，面板提前告知，自动更新不会安装这类版本） |
| 每条提示词的开销 | UserPromptSubmit 不支持 matcher，每条提示词都会运行一次入口 Hook（中位数约 0.43 s），即使未开启任务记录（`/充值` 需要它） |
| 上传进程的门槛只看配置文件 | 能识别插件禁用 / 卸载 / Hook 关闭 / 未信任；Hook 定义被改动（`modified`）只有 `hooks/list` 能判断，由控制面板显示，上传进程不感知 |
| 离线卸载 | 选择「删除后台数据」但当时离线：请求无法送达；卸载后不保留任何常驻组件补发（如实提示用户：联网后重新安装再撤销） |
| 降级模式下的充值 | 内核不兼容时 `/充值` 不可用；开始菜单的「Codex 充值」窗口仍可用，前提是该内核的 `account/read` 可用 |
| Codex 自动升级 | 兼容性在安装、打开面板时检测；Codex 在后台升级到不兼容版本后，到用户打开面板前不会提示（Hook 入口对未知字段宽容、异常一律 exit 0，不影响会话） |
| 数据目录共用 | 与开发版插件共用 `%LOCALAPPDATA%\CodexTaskRecorder` / `CodexCdkRecharge`；安装时询问卸载开发版插件，二者不应同时启用 |
| 运行时体积 | 私有 Python + Tk 约 27 MB（安装包压缩后 12.4 MB）；插件缓存中由 Codex 再复制一份 |
| 构建工具授权 | Inno Setup 要求商业用户购买授权（只涉及构建机，不涉及最终用户） |
| 更新包的信任链 | 安装包的真实性依赖 HTTPS 与清单中的 SHA-256；清单本身没有离线签名。自动安装模式会静默运行下载的程序，正式发布前建议对清单签名（公钥内置于 `product.json`）并对安装包做代码签名 |
| 后台与真实充值 | 三个后台均为模拟，真实充值、真实上传、真实更新尚未验证 |
| 脱敏 | 基于规则（P2/P3），无法保证识别所有敏感信息；授权说明中如实提示 |
